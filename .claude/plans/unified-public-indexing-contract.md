# Unified public indexing contract — Product + News

> Status: `VERIFIED — READY FOR COMMIT/DEPLOY` — production SQL boundary applied and verified; application code not pushed yet.
> Date: 2026-09-11.

## Goal

When a Product becomes public (`properties.is_active = true`) or a News article
becomes public (`news.is_published = true`), the application must propagate one
consistent public-indexing contract:

```text
public state
→ canonical URL source
→ metadata / JSON-LD route generation
→ sitemap + image-sitemap eligibility
→ Search Visibility deterministic registry
→ Next cache revalidation
→ SEO freshness queue
→ owner-visible propagation evidence
→ optional Search Console evidence (separate, never implied)
```

"Indexed" in this contract means **propagated and eligible inside the site**.
It does not claim that Google has crawled or indexed the URL. Google evidence is
only the `search_visibility_urls` inspection evidence returned by Search Console.

## Eligibility matrix

| Entity | Public state | Canonical source | Excluded when |
|---|---|---|---|
| Product | `is_active = true` | `buildProductPath()` + valid slug/area/listing type/public code | inactive or missing canonical parts |
| News | `is_published = true` | `/tin-tuc/{valid-slug}` | unpublished or malformed/missing slug |
| Area/Neighborhood | deterministic SEO quality gate | shared SEO evaluators | missing slug or quality gate failure |

Draft/pending entities may still be saved, but they must not be presented as
publicly indexable. User-listing approval is the Product publication event.

## Shared orchestration

Every public-impacting mutation uses the same server-side orchestration:

1. Build an allowlisted set of affected public paths (current and previous
   paths where a slug/taxonomy changed).
2. Call `revalidatePath` for those paths.
3. Upsert deduplicated `seo_freshness_jobs` for those paths.
4. Run deterministic `syncSearchVisibilityAudit` for public-impacting changes.
5. Return `paths`, queue status, and Search Visibility status as owner evidence.

Failure of the optional audit/queue layer must be visible as degraded evidence,
not silently claimed as complete; it must not roll back a successful content
mutation.

## Required routes and structures

- Product: detail URL, home/listing indexes, area and neighborhood landings,
  district/type composite landings, `/sitemap.xml`, `/sitemap-images.xml`.
- News: detail URL, News index, knowledge index, category, `/sitemap.xml`, and
  `/sitemap-images.xml`.
- Metadata and JSON-LD remain generated by the public route from canonical
  source data; no stored `schema_markup` field is treated as the source of truth.
